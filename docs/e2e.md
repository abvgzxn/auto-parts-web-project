# E2E-тесты Wellcar

Playwright проверяет сайт в настоящем Chromium. Конфигурация находится в
`playwright.config.ts`, проверки — в `tests/e2e/home.spec.ts`.
Код и содержимое сайта тесты не изменяют.

## Запуск в WSL

```bash
npm ci
npx playwright install chromium
npm run test:e2e
```

Если Playwright сообщает о недостающих системных библиотеках:

```bash
npx playwright install-deps chromium
npm run test:e2e
```

Установка системных библиотек требует sudo. Повторно устанавливать браузер
или библиотеки, если они уже доступны, не нужно.

При настройке 10 октября 2026 года пакет Playwright 1.64.0 и Chromium v1248
установлены. Проверка `ldd` обнаружила отсутствие `libnspr4.so`, `libnss3.so`,
`libnssutil3.so` и `libasound.so.2`. Остальные библиотеки исполняемого файла
найдены. Для этого окружения достаточно установить три отсутствующих пакета:

```bash
sudo apt-get install --no-upgrade libnspr4 libnss3 libasound2t64
npm run test:e2e
npx playwright show-report
```

Автоматическая установка остановилась с `sudo: a password is required`.
Ошибка запуска браузера:

```text
error while loading shared libraries: libnspr4.so: cannot open shared object file: No such file or directory
```

Пробный запуск вне sandbox успешно запустил Next.js и дождался готовности
главной страницы. Все 12 экземпляров тестов завершились ошибкой при создании
браузера из-за указанных библиотек, до проверок сайта. Скриншоты не созданы.
ESLint, TypeScript и обнаружение тестов (`playwright test --list`) прошли.

Playwright сам запускает `next dev` на `http://127.0.0.1:3000` и ждёт HTTP-ответа
главной страницы до 120 секунд. В локальном режиме он может использовать уже
запущенный сервер на этом адресе: убедитесь, что это именно Wellcar.
В CI всегда запускается собственный сервер. Ограничение Codex sandbox
`listen EPERM` устраняется запуском команды в обычном терминале WSL
или с разрешением запуска вне sandbox; конфигурация Next.js для этого не меняется.

Профили: desktop 1440×900 и mobile 390×844. Дополнительно проверяется отсутствие
горизонтального переполнения на ширинах 320, 375, 390 и 414 с закрытым и открытым
меню. Две мобильные проверки намеренно пропускаются в desktop-профиле.
MAX и `tel:` проверяются по адресам ссылок без внешних переходов и звонков;
это не проверка доступности аккаунта MAX.

## Скриншоты и диагностика

```bash
npx playwright show-report
```

Тест скриншотов сохраняет `home.png` (вся страница) и `hero.png` для каждого
профиля в `test-results/` и прикрепляет их к HTML-отчёту `playwright-report/`.
Это изображения для визуального анализа, а не сравнение с эталоном.
Для них тест ждёт загрузки изображений сайта и шрифта. Содержимое внешней карты
может отличаться между запусками. При сбое сохраняются скриншот и trace.

```bash
npx playwright show-trace test-results/<папка-теста>/trace.zip
```

Отчёты, trace и скриншоты игнорируются Git. Оба профиля используют headless
Chromium; мобильный профиль также включает touch и мобильное поведение браузера.

## Повторная проверка после установки библиотек

`npm run test` — алиас `npm run test:e2e`. Повторный запуск 10 октября 2026 года
вне Codex sandbox: **10 passed, 2 skipped, 0 failed**. ESLint и
`npx tsc --noEmit` прошли. Пропущены проверки мобильного меню и мобильного
переполнения в desktop-профиле.

Предыдущие два падения (8 passed, 2 failed, 2 skipped) были проверками H1:
JSX удалял перевод строки перед `<span>`, поэтому DOM содержал «маслав».
Явный `{" "}` после «масла», уже присутствовавший при повторной проверке,
сохраняет пробел в DOM. CSS `block`, цвет и отступ второй части заголовка
сохранены; ожидаемый текст теста не менялся.

Положение `storefront.webp` при начальной загрузке без прокрутки:

| Viewport | Верх фотографии | Высота первого экрана | Загрузка |
| --- | ---: | ---: | --- |
| 1440×900 | 2736 px | 900 px | lazy |
| 390×844 | 4414,5 px | 844 px | lazy |

Фотография магазина находится ниже первого экрана, поэтому eager не добавлен.
Предупреждение Next.js повторилось во время мобильного теста скриншотов,
который программно прокручивает страницу к lazy-изображениям. В установленном
Next.js проверка LCP в `get-img-props.js` не проверяет исходные координаты
изображения. Отдельное измерение начальной загрузки зарегистрировало Hero
как LCP-изображение в обоих профилях, без предупреждения о фотографии магазина.
Следовательно, предупреждение в таком прогоне не доказывает необходимость
eager-загрузки фотографии магазина.

Просмотрены скриншоты всей страницы, Hero и первого экрана. Hero полностью
помещается на первом экране: низ на 715 px desktop и 786 px mobile. Текст
и кнопки не обрезаны, наложений не видно. Измеренное горизонтальное
переполнение — 0 px в обоих профилях; тест дополнительных мобильных ширин
также прошёл. На мобильном изображение автомобиля почти скрыто существующим
затемнением 98%; это наблюдение для согласования дизайна, стили не изменены.
В обоих полных скриншотах карта отображается пустым блоком: тест не ждёт
готовности внешнего iframe, поэтому по этим изображениям нельзя установить
причину или утверждать, что карта неисправна. Кнопка Next.js внизу первого
экрана относится к режиму разработки.
